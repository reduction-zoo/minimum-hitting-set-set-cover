## Correctness

The declared source and target are exact optimization problems (`question.md`, `work/contract.md:3-7`). The current `F` (`work/algorithm.py:9-16`) constructs one target set for each distinct source element occurring in a member. Its target universe has one element per source member. Both counts are bounded by the written input length, even when `universe_size` has a huge decimal value. The constructed target is legal: each emitted member index is in `[0,m)`, and no target set repeats an index. `G` (`work/algorithm.py:19-24`) rebuilds the same sorted active-element list from the source and maps every valid selected target index to its original source element. It carries `NO-SOLUTION` through. Both CLI modes (`work/algorithm.py:27-33`) use only their input, emit JSON, and run independently.

The proof at `work/proof.md:7,11-15` supplies the needed premise: for every target index set `I`, its decoded source set meets source member `C_j` exactly when `I` covers target element `j`. The sorted active list is injective, so cardinality is preserved. Every optimal source hitting set contains only active elements, since removing an unused element preserves feasibility and reduces size. Thus source and target feasibility and optimum cardinality agree, and **every** optimal target output, including each tie, recovers an optimal source output. When either side is infeasible, both are and `NO-SOLUTION` is the valid answer; otherwise a valid optimum exists. Empty families, empty members, repeated members, unused elements and the empty universe follow from the same equivalence. This also checks the local experience claim in `research/experience/active-support-for-succinct-universe.md:3`: its active-support premise applies here; the claim would not apply to a requirement to preserve every nonoptimal feasible witness.

The repaired size argument in `work/proof.md:19-21` is sound for this JSON encoding. With input length `L`, the number of source members `m`, written incidences `r`, and active elements `q` are each at most `O(L)`, regardless of the numeric universe size. The nested construction makes at most `qm=O(L²)` integer membership tests; parsing, integer hashing/comparison, sorting, and JSON conversion on at most `L`-digit integers have polynomial bit cost. Even worst-case hash collisions give polynomially many comparisons. The target writes `q` sets and exactly `r` incidences, all target indices using `O(log(L+1))` decimal digits. Recovery rebuilds at most `r` incidences and writes at most `q` source indices, each with at most `L` digits. The coarse polynomial bounds stated in the proof are adequate. `sys.set_int_max_str_digits(0)` at `work/algorithm.py:6` removes the Python 3.12 decimal conversion cap for legal finite JSON integers. No enumeration or output scale depends on the numeric value of `n`.

## Novelty

The combinatorial theorem is known. Checked 2026-09-23: [Cygan et al., *On Problems as Hard as CNF-SAT*, §4.1, paragraph before Observation 4.1](https://sites.cs.ucsb.edu/~daniello/papers/problemsAsHardAsSatJ.pdf) states the incidence-dual one-to-one correspondence between hitting sets and set covers; cardinality preservation and the optimum claim follow immediately. The [problem-reductions issue #1094, “Reduction Algorithm” and “Size Overhead”](https://github.com/CodingThrust/problem-reductions/issues/1094) states this direction, recovery, and corner cases. Its version emits a set for every source universe element; omitting inactive elements for an exact optimum is an elementary encoding repair, not a new combinatorial theorem. The issue showed no linked branch or pull request when checked, but that does not prove no executable adapter exists elsewhere. A complete search of implementations and historical priority remains unresolved. The established mathematical result does not defeat the fixed question, which explicitly asks for an executable full-domain rule.
